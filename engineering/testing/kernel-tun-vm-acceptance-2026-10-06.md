# Windows TUN 大版本候选隔离验收

状态：NOT RUN。本清单是已实现批次的运行验收任务，不是通过证据。源码 `f0b1b7eba271b2402a9a82809bec0ea53d9a3e8e`，普通 Windows amd64 预览；固定 Mihomo v1.19.32 加项目生命周期补丁。包摘要以 `kernel-tun-reliability-2026-10-06.md` 的最终构建记录为准。

后续需求修订：用户明确要求完整启动 Windows 应用即启动代理与 TUN。新候选按 `engineering/plans/windows-startup-tun-2026-10-06.md` 的 S01–S08 及其测试报告验收；下表 W01/W05 的启动只读预期仅适用于上述旧源码，不可沿用到新候选。传输重连仍只读，手动关闭后不因后台刷新重开；W02–W04 的权限/重试场景需从新的自动启动入口触发。其余适用系统验收继续保留，不把旧包的未运行状态改为新包通过。

## 进入条件

1. 用户提供并批准操作可恢复的 Windows VM 或专用测试机；记录系统版本、架构、网络类型、快照名和恢复点。不要在开发工作站执行本表的服务/路由故障注入。
2. 核对 ZIP SHA256、解压文件清单、COMPONENTS.json、CORE-PATCH.json 和源码提交。UI/Agent/Core/Helper 必须成套；保留旧包和测试配置快照。
3. 使用获准的测试配置/节点；不要把账号、订阅令牌或完整配置写入普通报告。准备可控制的 IPv4/IPv6、TCP/UDP 和 DNS 测试目标。缺 IPv6 或 UDP 条件时逐项标 NOT RUN，不能用 IPv4 HTTP 代替。
4. UAC 由用户操作；权限拒绝测试不能关闭系统安全策略。普通预览不安装严格 WFP 驱动，不启用测试签名。

每个用例记录：起始组件 hash/实例、用户动作、期望、实际、PASS/FAIL/NOT RUN、脱敏截图/日志位置、复现次数及恢复状态。分别记录“网卡存在且 up”“路由符合配置”“指定流量经过预期节点”。

## 执行顺序与用例

| ID | 初始条件与动作 | 预期结果与证据 |
|---|---|---|
| W01 | 新包、普通用户、Core 在本地运行，TUN 初始关 | 状态观测为关；显示的组件实例与当前进程一致，无自动 UAC |
| W02 | 显式开启 TUN，用户拒绝 UAC | 显示失败/需授权，无绿色成功；不因偏好保存、轮询、切页或配置 debounce 再次弹 UAC |
| W03 | 再次明确重试并批准授权 | 旧 Core 停止确认后才接新实例；Helper/Core hash 匹配；只有新 listener 和对应接口 up 后显示开启 |
| W04 | 开启成功后关闭 TUN，再重复关闭 | off 来自实际观测；重复操作不创建新 Core、不残留开启标记；记录实际网卡/路由回收情况 |
| W05 | 保存开意图但代理未启动；关闭并重新打开 UI | 读取当前 Core，不能仅凭已保存偏好显示开启；挂接既有 Agent 不自动重启失败或停止的 Core |
| W06 | 已开启时只关闭窗口，再重新打开 | 依照既有“只断开 UI”语义保留后台；重新观测同一实例；不把窗口关闭当 TUN 已关 |
| W07 | 等待授权或后端交接期间发出关闭、退出或重启 | 旧意图作废、交接串行；迟到授权/回复不能再开启网卡；不出现两个并行当前 Core |
| W08 | TUN 已开启，受控断开 UI-Agent 通道 | 立即或有界查询超时后撤销开启断言；恢复连接后重新核对实例和状态，不能复用旧绿色 |
| W09 | TUN 已开启，受控结束 Core | UI 不永久显示开启；后台恢复有界，恢复结果取实际 listener/接口；失败可解释，不循环 UAC |
| W10 | 让 Helper 重启而旧 Core 退出情况未知 | 带旧 owner 的 stop 返回未确认；Agent 保留归属并报告失败，不假称停止后启动新会话；不自动强杀未知进程 |
| W11 | 使用旧 Agent、旧 Helper、与 Core hash 不匹配的 Helper 三组混版本 | 缺合同/hash 不符时明确提示，旧 Agent 在 UAC/stop 前拒绝自动迁移；不能将 ping 当权限或运行证明 |
| W12 | 外部控制器改变 tun.enable，随后由 UI 读取/切换 | UI 收敛到实际 listener 状态；外部配置与 UI 操作不产生旧 revision 覆盖；保留合法 auto-route=false 语义 |
| W13 | 受控接口缺失/down、权限或接口查询失败 | failed/unknown 有对应说明；不显示“已成功开启”；配置接受与网卡成功分开 |
| W14 | 快速开→关→开，配置更新与重连同时发生 | 最后意图获执行，过期操作无效；无并行迁移、重复 Core、无限队列或授权风暴 |
| W15 | 设置页、仪表盘、托盘、热键，宽窗和窄窗 | 开启/关闭/未知/等待/失败一致；支持重试和取消待开启；错误文字、焦点和交互可用 |
| W16 | 旧 mixed/gvisor 配置及新支持的 mips 解析配置 | 不静默替换原用户栈；加载成功与实际流量结果分别记录；不把可解析当所有栈已验收 |
| W17 | 流量矩阵：TCP、UDP、DNS、IPv4、IPv6，规则与全局两种模式 | 依据预期规则验证出站与直连；记录节点/连接日志的脱敏证据。网卡 up 不能代替此项 |
| W18 | Antigravity IDE 的登录、请求和长连接场景 | 对具体域名/进程/协议判断命中规则和实际出站，逐项记录；不能用浏览器出口 IP 代替 IDE 结果 |
| W19 | 未登录及测试账号购买页 | 套餐/价格可见；两个微信和复制、兑换查询/确认/历史、账号/订阅入口均保留；本批不需要再次消耗礼品卡 |
| W20 | 成套升级及回退演练 | 保存配置，退出匹配后台，再按已批准 VM 流程切整套组件；旧包可恢复，配置/购买数据未丢失，失败有明确记录 |

W10 若产生未确认孤儿进程，停止后续启动测试，保留日志并恢复 VM 快照；不要以重装/强杀后可用掩盖该用例结果。某一特定应用不走代理时，继续区分规则、DNS、IPv6、协议和应用自身代理设置，不能再次把“TUN 开关为开”当作所有流量已接管。

## 晋级条件

本批普通预览只有在 W01–W15 的适用关键行为、W17 的可用网络矩阵以及成套回退通过后，才具备提交 `development → main` 批次验收的运行证据。W18 必须有独立应用证据才能宣布最初 Antigravity 问题解决。缺环境、失败或不适用项须逐项解释；不得从自动化通过推断实机通过。主线合并、正式签名和发布仍按当次用户授权执行。
