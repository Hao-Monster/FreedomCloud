# FlClashX strict capture (WFP callout)

This directory contains the Windows kernel-mode callout boundary used by the
strict per-application mode.  It is deliberately a small, auditable WDM
driver: policy is supplied by the elevated Helper through a versioned IOCTL,
and the callout is registered on the ALE connect-redirect IPv4/IPv6 layers.

The current implementation is a **fail-closed capture skeleton**.  A selected
process is blocked until the user-mode broker has installed a complete,
authenticated redirect path to Mihomo.  It never silently permits a selected
flow or injects a DLL.  The redirect data-plane (socket ownership, TCP/UDP
mapping and lifecycle recovery) remains a separate milestone and must not be
represented as complete by a test package.

## Build (development only)

The project requires Visual Studio with the Windows Driver Kit (WDK).  A
developer build can be produced with:

```powershell
& "$env:ProgramFiles\Microsoft Visual Studio\18\Insiders\MSBuild\Current\Bin\MSBuild.exe" `
  "$PSScriptRoot\strict_capture.vcxproj" /p:Configuration=Release /p:Platform=x64 /m
```

Do not enable test-signing or install/load the driver on the development host;
the repository's network policy forbids changing its WFP/TUN/DNS state.

## Signing and HLK

`build-test-sign.ps1` only signs a local development artifact when explicitly
requested.  Production release requires the publisher's code-signing identity,
Microsoft Partner Center attestation/WHQL access, and an HLK controller/client
that runs the official Windows 11 test matrix.  Those identities and machines
cannot be generated by source code.
